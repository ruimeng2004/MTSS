# 个体 Bug 平衡分析报告

**分析日期**: 2026-01-17  
**数据集**: Defects4J (698 bugs)  
**分析目标**: 识别所有 698 个 bugs 中有多少是任务建模平衡的

---

## 执行摘要

本报告分析了 Defects4J 数据集中所有 698 个 bugs 在两种任务建模（edit vs gen）下的 PPL 差距，识别出不同阈值下的平衡 bug 数量。

**关键发现**:
- **qwen3_coder**: 5.4% - 18.9% 的 bugs 是平衡的（取决于阈值）
- **qwen3_30b**: 8.6% - 34.5% 的 bugs 是平衡的（取决于阈值）
- **推荐阈值（20%）**: qwen3_coder 64 bugs (9.2%), qwen3_30b 100 bugs (14.3%)
- **跨模型一致性低**: 两个模型识别的平衡 bug 重叠度仅 8.6% (Jaccard)

---

## 1. 分析方法

### 1.1 PPL 差距定义

对于每个 bug，计算其在 edit 和 gen 任务下的 PPL 相对差距：

```
gap = |PPL_edit - PPL_gen| / min(PPL_edit, PPL_gen) × 100%
```

### 1.2 平衡 Bug 定义

如果一个 bug 的 gap 小于指定阈值，则认为它是"平衡的"，即两种任务建模表现相近。

### 1.3 阈值设置

分析了 8 个不同的阈值：5%, 10%, 15%, 20%, 25%, 30%, 40%, 50%

## 7. 与聚类方法的对比

### 7.1 方法对比

| 维度 | 直接 PPL 判断 | 聚类方法 |
|------|-------------|---------|
| **识别数量** (20%) | 64-100 bugs | 61-101 bugs |
| **覆盖率** | 9.2%-14.3% | 8.7%-14.5% |
| **计算复杂度** | O(n) | O(n²) 或更高 |
| **实现复杂度** | 简单 | 复杂 |
| **依赖** | 仅需 PPL 数据 | 需要聚类、采样、投票 |
| **可解释性** | 高 | 中 |

### 7.2 结论

**直接 PPL 判断方法优于聚类方法**:
1. **相同的覆盖率**: 识别出的平衡 bug 数量相当
2. **更简单**: 不需要复杂的聚类流程
3. **更快**: 线性时间复杂度
4. **更直接**: 直接基于 PPL 差距判断，逻辑清晰

**聚类方法的唯一优势**:
- 可以利用簇的集体信息
- 但由于 70-80% 是单点簇，这个优势几乎不存在

## 8. 实施建议

### 8.1 推荐方案：直接 PPL 差距判断

```python
def select_task_modeling(bug, model, threshold=0.20):
    """Select task modeling strategy for a bug.
    
    Args:
        bug: Bug identifier.
        model: Model name (qwen3_coder or qwen3_30b).
        threshold: PPL gap threshold (default 20%).
    
    Returns:
        Strategy: "edit", "gen", or "both".
    """
    ppl_edit = get_ppl(bug, model, "edit")
    ppl_gen = get_ppl(bug, model, "gen")
    
    gap = abs(ppl_edit - ppl_gen) / min(ppl_edit, ppl_gen)
    
    if gap < threshold:
        return "both"
    elif ppl_edit < ppl_gen:
        return "edit"
    else:
        return "gen"
```

### 8.2 实施步骤

#### 阶段 1：验证（1-2 周）

1. 在小规模数据上测试"both"策略
2. 对比 Win Rate 提升
3. 评估额外计算成本

**成功标准**: Win Rate 提升 ≥ 2%

#### 阶段 2：优化（2-3 周）

1. 调整阈值（测试 15%, 20%, 25%）
2. 分析不同项目的最佳阈值

#### 阶段 3：部署（1 周）

1. 全面部署到生产环境
2. 监控性能和成本
3. 收集用户反馈

| 用户体验下降 | 低 | 提供清晰的说明 |

## 9. 结论

### 9.1 主要发现

1. **平衡 bug 存在但数量有限**
   - qwen3_coder: 9.2% (64 bugs) @ 20% 阈值
   - qwen3_30b: 14.3% (100 bugs) @ 20% 阈值

2. **模型差异显著**
   - qwen3_30b 识别出更多平衡 bug（+56.3%）
   - qwen3_30b 的 PPL 分布更集中、更平衡

3. **跨模型一致性低**
   - Jaccard 相似度仅 8.6% @ 20% 阈值
   - 说明"平衡"是模型相关的概念

4. **直接判断优于聚类**
   - 相同的覆盖率，更简单的实现
   - 不需要复杂的聚类流程

### 9.2 实施建议

✓ **推荐**: 使用直接 PPL 差距判断，阈值 20%

✓ **预期收益**: Win Rate 提升 2-5 个百分点

✓ **实施路径**: 验证 → 优化 → 部署

### 9.3 未来工作

1. **理解平衡 bug 的特征**
   - 为什么这些 bug 在两种建模下表现相近？
   - 是否有共同的代码模式或 bug 类型？

2. **改进任务建模**
   - 设计更好的任务表示
   - 减少平衡 bug 的数量

3. **多任务学习**
   - 训练同时擅长 edit 和 gen 的模型
   - 消除任务选择的需求
