## 研究目标

1. 有多少 bug 对任务建模选择敏感？
2. 有多少 bug 的两种建模效果差不多？
3. 是否需要引入三分类系统（edit/gen/默认）？

## 5. 三分类系统可行性分析

### 当前二分类系统

- **Edit**: 适合 edit 的 bug
- **Gen**: 适合 gen 的 bug

### 提议的三分类系统

- **Edit**: 适合 edit 的 bug（相对差距大，edit 更好）
- **Gen**: 适合 gen 的 bug（相对差距大，gen 更好）
- **Default**: 两者差不多的 bug（相对差距小，用默认策略）

### 可行性评估

#### 方案 1: 严格阈值（< 5%）

| 模型 | Default 类占比 | Edit 类占比 | Gen 类占比 |
|------|---------------|------------|-----------|

**评估**: Default 类占比太小（3-4%），引入三分类的收益有限。

**评估**: Default 类占比仍然较小（9-14%），但可以考虑。

#### 方案 3: 动态阈值（P25）

## 6. 结论与建议

### 主要发现

1. **大部分 bug 对任务建模敏感**
   - qwen3_coder: 90.8% 的 bug 差距 ≥ 20%
   - qwen3_30b: 85.7% 的 bug 差距 ≥ 20%

2. **差距可忽略的 bug 很少**
   - qwen3_coder: 仅 3.2% 的 bug 差距 < 5%
   - qwen3_30b: 仅 4.2% 的 bug 差距 < 5%

3. **存在极端差异**
   - 最大差距可达数十万倍
   - 中位数差距也达到 88-243%

4. **两个模型的偏好不同**
   - qwen3_coder 偏好 Gen（55.6%）
   - qwen3_30b 偏好 Edit（52.3%）

### 三分类系统建议

#### 不建议引入三分类（严格阈值）

**理由**:
- 差距 < 5% 的 bug 仅占 3-4%，收益太小
- 增加系统复杂度，但覆盖范围有限

#### 可以考虑三分类（宽松阈值）

**方案**: 使用 P25 作为阈值
- qwen3_coder: 差距 < 71.8% → Default
- qwen3_30b: 差距 < 35.3% → Default

**收益**:
- 覆盖 25% 的 bug
- 这些 bug 可以跳过任务建模选择，节省计算成本
- 对性能影响较小（因为差距本身就不大）

**实现**:
```python
if ppl_gap < threshold:
    strategy = "default"  # 使用默认策略（如 gen）
else:
    strategy = select_best(edit_ppl, gen_ppl)
```

### 最终建议

1. **当前阶段**: 保持二分类系统
   - 大部分 bug 对任务建模敏感，选择很重要
   - 系统简单，易于理解和维护

2. **未来优化**: 如果计算成本是瓶颈，可以考虑：
   - 引入"快速路径"：对差距 < P25 的 bug，直接使用默认策略
   - 节省 25% 的 PPL 计算成本
   - 性能损失可控（因为这些 bug 本身差距就小）

3. **进一步研究**:
   - 分析哪些类型的 bug 差距小（如特定项目、特定错误类型）
   - 研究是否可以通过 bug 特征预测差距大小
   - 探索自适应阈值策略
