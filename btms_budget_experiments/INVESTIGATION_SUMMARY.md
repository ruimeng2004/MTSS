# BTMS路由评估问题排查总结

**排查时间**: 2026-02-22  
**状态**: ✅ 根本原因已确认

---

## 📋 问题描述

6个不同权重配置的BTMS路由实验产生完全相同的修复成功率（518 fixed / 180 failed）。

---

## 🔍 排查过程

### 第一步：确认现象
- ✅ 6个实验确实产生相同结果（518/180）
- ✅ Fixed 50-50意外成为最优策略（551/180）

### 第二步：检查路由决策
- ✅ 所有实验的Bug级路由分布相同：289 edit / 409 gen
- ✅ 所有实验的簇级决策相同：48 edit簇 / 52 gen簇

### 第三步：分析cluster_choices
- ✅ 不同实验的置信度确实不同
- ❌ 但所有实验的edit ratio都在0.5±0.02范围内
- ❌ Ratio标准差仅0.0028-0.0056

### 第四步：检查权重配置
- ✅ 配置文件确实不同（0.4/0.4/0.2 vs 0.33/0.33/0.34等）
- ✅ 权重正确加载到HybridMetric

### 第五步：分析混合指标计算
- 🔴 **找到根因**: 置信度缩放机制失效
- 🔴 **PPL Gap极小**: 平均0.017，导致PPL置信度仅0.0017
- 🔴 **最终调整公式**: 85%的ratio偏离被压制回0.5

### 第六步：分析基础组件
- 🔴 **PPL Ratio完全失效**: std=0.007，无区分度
- ⚠️ **Vote Ratio有区分度**: std=0.317，但平均值恰好0.5
- 🔴 **Edit/Gen PPL几乎相同**: 无法提供有效信号

---

## 🎯 根本原因

### 技术层面

1. **置信度缩放参数错误**
   ```python
   ppl_conf = min(abs(gap) / 10.0, 1.0)  # 缩放因子10.0过大
   ```
   - 实际gap平均0.017，但公式假设gap在0-10范围
   - 导致置信度比预期低**600倍**

2. **最终调整公式过度保守**
   ```python
   final_ratio = 0.5 + (weighted_ratio - 0.5) * overall_confidence
   ```
   - 低置信度导致ratio被拉回0.5
   - **85%的差异被抹平**

3. **PPL组件完全失效**
   - Edit和Gen的PPL几乎相同（gap平均0.017）
   - PPL Ratio标准差仅0.007，无区分能力

### 数据层面

**Edit vs Gen模式在当前数据集上难以区分**:
- PPL几乎相同
- Vote比例接近50-50
- 这解释了为什么Pure Edit策略最优（78.9% vs 74.2%）

## 💡 修复方案

### 短期方案：调整缩放参数

```python
# 调整PPL置信度缩放
ppl_conf = min(abs(gap) / 0.15, 1.0)  # 10.0 → 0.15

# 调整Vote置信度阈值
vote_conf = min(avg_gap / 0.05, 1.0)  # 0.5 → 0.05

# 选项1: 移除最终调整
final_ratio = weighted_ratio

# 选项2: 减弱调整影响
final_ratio = 0.5 + (weighted_ratio - 0.5) * sqrt(overall_confidence)
```

**预期效果**:
- Ratio标准差从0.030提升到0.075-0.192
- 不同配置会产生不同的路由决策

### 长期方案：重新审视实验设计

由于Edit和Gen模式本质上难以区分，需要考虑：

1. **是否应该focus在提升Edit性能**
   - Pure Edit已达78.9%
   - 动态路由仅74.2%，损失6.7%

2. **是否需要更好的区分指标**
   - 当前PPL无法区分Edit/Gen
   - 需要寻找更有效的性能预测指标

3. **是否应该调整实验目标**
   - 从"寻找最优路由策略"转向"理解Edit优势原因"
