# BTMS路由评估诊断报告

**诊断时间**: 2026-02-22  
**问题**: 多个不同配置的实验显示相同的修复成功率

---

## 🔴 核心问题发现

### 1. 评测结果异常相同

| 配置 | 修复数 | 失败数 | 成功率 |
|------|--------|--------|--------|
| **Exp 1 - Default** | 518 | 180 | 74.2% |
| **Exp 2 - Balanced** | 518 | 180 | 74.2% |
| **Exp 3 - PPL Heavy** | 518 | 180 | 74.2% |
| **Exp 4 - Vote Heavy** | 518 | 180 | 74.2% |
| **Exp 5 - Size Heavy** | 518 | 180 | 74.2% |

**异常现象**: 6个不同权重配置的实验产生完全相同的结果（518/180）

---

## 🔍 根本原因分析

### 问题1: 所有实验的路由决策完全相同

**Bug级路由分布** (所有实验):
- Edit: 289 bugs (41.4%)
- Gen: 409 bugs (58.6%)
- Edit成功: 244, Gen成功: 274

**簇级决策分布** (所有实验):
- Edit簇: 48个
- Gen簇: 52个

### 问题2: 混合指标ratio高度聚集在0.5附近

| 实验配置 | Min Ratio | Max Ratio | Mean | Std Dev | 簇级Edit/Gen |
|---------|-----------|-----------|------|---------|-------------|
| Exp1-Default | 0.4819 | 0.5061 | 0.4993 | **0.0034** | 48/52 |
| Exp2-Balanced | 0.4717 | 0.5104 | 0.4991 | **0.0049** | 48/52 |
| Exp3-PPL Heavy | 0.4849 | 0.5053 | 0.4995 | **0.0028** | 48/52 |
| Exp5-Size Heavy | 0.4670 | 0.5124 | 0.4990 | **0.0056** | 48/52 |

**关键发现**:
- ✅ 所有实验的edit ratio**标准差极小** (0.0028-0.0056)
- ✅ 所有实验的**平均ratio都在0.499左右**
- ✅ 尽管不同实验使用了不同的权重配置，ratio分布几乎相同

### 问题3: 评估代码使用硬阈值0.5

**代码逻辑** ([run_btms_routing_eval.py](run_btms_routing_eval.py#L162-L165)):
```python
elif decision == 'mixed':
    # For mixed, use ratio to probabilistically choose
    # For evaluation, we'll use the higher ratio
    edit_ratio = ratio.get('edit', 0.5)
    modeling_type = 'edit' if edit_ratio >= 0.5 else 'gen'
```

**问题**:
- 使用硬阈值0.5将连续的ratio映射到离散的edit/gen决策
- **微小的ratio差异** (例如0.4982 vs 0.5006) 被放大为完全不同的决策
- 但由于所有实验的ratio分布都在0.5附近，**阈值抹平了不同配置的差异**

### 问题4: 大簇偏向Gen导致不平衡分布

**最大的10个簇分析**:

| 簇ID | Bug数 | Edit Ratio | 决策 |
|------|-------|------------|------|
| 7 | 21 | 0.4993 | **gen** |
| 21 | 17 | 0.4995 | **gen** |
| 1 | 16 | 0.4982 | **gen** |
| 16 | 16 | 0.4967 | **gen** |
| 80 | 14 | 0.4987 | **gen** |
| 13 | 14 | 0.4926 | **gen** |
| 19 | 13 | 0.4990 | **gen** |
| 58 | 13 | 0.4997 | **gen** |
| 31 | 13 | 0.5006 | edit |
| 66 | 13 | 0.4819 | **gen** |

**发现**: 前10大簇中有9个被分配为gen（都因为ratio < 0.5），这些大簇包含了更多的bug，导致：
- 虽然簇级决策是48/52（相对平衡）
- 但bug级分布是289/409（明显不平衡）

## 💡 深层原因

### 1. 混合指标计算问题

**cluster_choices.json结构**:
```json
{
  "cluster_id": 0,
  "decision": "mixed",  // ✅ 所有簇都是'mixed'
  "ratio": {
    "edit": 0.5001955,  // ⚠️ 所有ratio都在0.5±0.02范围内
    "gen": 0.4998045
  },
  "confidence": 0.1252,
  "metadata": {
    "metric": "hybrid",
    "cluster_size": 6
  }
}
```

**问题**:
1. **所有簇的decision都是'mixed'**，从未产生明确的'edit'或'gen'决策
2. **所有ratio都在0.5附近微小波动**，说明混合指标没有产生有意义的区分
3. **不同权重配置** (Default vs PPL Heavy vs Size Heavy) **未能改变ratio分布**

### 2. 可能的原因

#### 原因A: 混合指标权重未生效
- 不同实验的权重配置可能没有正确传递到混合指标计算中
- 所有实验可能实际使用了相同的默认权重

#### 原因B: 混合指标计算公式问题
- 混合指标公式可能设计为总是输出接近0.5的值
- 归一化或缩放步骤可能抹平了差异

#### 原因C: 基础指标缺乏区分度
- PPL、Vote、Size等基础指标本身可能在edit/gen之间没有明显差异
- 导致无论如何组合权重，结果都接近50-50

## 📊 实际修复成功率分析

### Fixed 50-50策略的意外表现

**结果**: 551 fixed (78.9%) - **最好的性能**

**机制解释**:
```python
# 评估逻辑中当权重为0.5时优先选择Edit
modeling_type = 'edit' if edit_ratio >= 0.5 else 'gen'
```

由于阈值是 `>=`, Fixed 50-50实际执行为:
- **所有簇的ratio = 0.5**
- **所有698个bug都路由到Edit**
- 这意外地提供了纯Edit模式的性能上限

### 动态路由的代价

| 策略 | Edit修复 | Gen修复 | 总修复 | vs纯Edit |
|------|---------|---------|--------|---------|
| Pure Edit (Fixed 50-50) | 551 | 0 | 551 | - |
| All Dynamic | 244 | 274 | 518 | **-33** (-6.0%) |
| PPL Only | - | - | 508 | **-43** (-7.8%) |

**关键洞察**:
1. **纯Edit策略最优**: Edit模式在此数据集上表现统治级优势
2. **动态路由造成损失**: 用Gen替换Edit导致总修复数下降
3. **即使Gen贡献274个修复**, 但这274个位置如果留给Edit可能修复更多

## 🎯 建议措施

### 短期措施 (修正当前评估)

1. **检查混合指标计算代码**
   - 验证不同实验的权重配置是否真正生效
   - 检查是否所有实验都使用了相同的权重

2. **分析基础指标的区分度**
   ```bash
   # 检查PPL、Vote、Size在edit/gen之间是否有差异
   python analyze_metric_discrimination.py
   ```

3. **使用概率采样代替硬阈值**
   ```python
   # 当前: 硬阈值
   modeling_type = 'edit' if edit_ratio >= 0.5 else 'gen'
   
   # 建议: 概率采样
   modeling_type = 'edit' if random.random() < edit_ratio else 'gen'
   ```

### 中期措施 (改进指标设计)

1. **重新设计混合指标**
   - 确保不同组件能产生有意义的差异
   - 避免过度平滑或归一化

2. **验证权重配置的影响**
   - 运行极端配置测试（如100% PPL, 100% Size）
   - 确认不同权重能产生不同的ratio分布

3. **考虑其他决策策略**
   - Top-k选择（选择置信度最高的k个簇用edit）
   - 动态阈值（基于ratio分布自适应调整）

### 长期措施 (重新评估实验设计)

1. **重新审视Edit vs Gen的性能差距**
   - Pure Edit: 551/698 (78.9%)
   - Best Dynamic: 518/698 (74.2%)
   - **差距达6.7%**，需要分析是否值得引入动态路由

2. **分析Edit优势的原因**
   - 是否因为数据集特性
   - 是否因为模型训练方式

3. **考虑混合策略的价值主张**
   - 如果Edit始终更好，动态路由的意义何在
   - 是否应该focus在提升Edit性能，而非路由优化

## 结论

当前的BTMS路由评估存在**系统性问题**：

1. **所有动态路由实验产生相同结果**（518/180），因为混合指标ratio都聚集在0.5附近
2. **不同权重配置未能产生不同的路由决策**，所有实验的bug级分布都是289 edit / 409 gen
3. **固定50-50策略意外成为纯Edit策略**，提供了最好的性能（551/698）
4. **硬阈值0.5放大了微小差异但抹平了配置差异**，导致评估失效

**需要立即**检查混合指标计算逻辑和权重配置加载机制，确保不同实验配置能产生有意义的差异。

## 🔬 深层原因分析（2026-02-22更新）

### 技术根因已确认

**完整技术分析**: 参见 [HYBRID_METRIC_ROOT_CAUSE_ANALYSIS.md](HYBRID_METRIC_ROOT_CAUSE_ANALYSIS.md)

#### 问题1: PPL组件完全失效
- **PPL Gap极小**: 平均仅0.017，最大0.14
- **PPL Ratio无区分度**: std=0.007，范围0.465-0.511
- **原因**: Edit和Gen模式的PPL几乎相同，无法提供有效信号

#### 问题2: 置信度缩放参数错误
```python
ppl_conf = min(abs(gap) / 10.0, 1.0)  # 缩放因子10.0过大
```
- 实际gap平均0.017，需要≥10才能达到置信度1.0
- 导致PPL置信度平均仅0.0017，最大0.014
- **置信度比预期低600倍**

#### 问题3: 最终调整公式过度压制
```python
final_ratio = 0.5 + (weighted_ratio - 0.5) * overall_confidence
```
- Overall置信度平均仅0.146
- **85%的ratio偏离被压制**
- 例：weighted=0.6 → final=0.513 (仅保留13%偏离)

#### 问题4: Vote组件虽有区分度但平均值恰好是0.5
- Vote Ratio: std=0.317（有区分度）
- 但平均值=0.493，基于0.5阈值划分时正好48/52
- 导致所有实验产生相同的路由决策

### 完整因果链

```
Edit/Gen PPL几乎相同
    ↓
PPL Gap极小 (avg=0.017)
    ↓
PPL Ratio无区分度 (std=0.007)
    ↓
PPL置信度极低 (avg=0.0017) ← 缩放因子10.0过大
    ↓
Overall置信度低 (avg=0.146)
    ↓
最终调整压制85%偏离
    ↓
Final Ratio聚集在0.5 (std=0.003-0.006)
    ↓
不同权重配置差异被抹平
    ↓
所有实验路由决策相同 (48 edit / 52 gen簇)
    ↓
所有实验Bug级分布相同 (289/409)
    ↓
所有实验修复成功率相同 (518/180)
```

### 修复验证

**参数调整效果**:

| 方案 | Ratio Std | Ratio Range | 效果 |
|------|-----------|-------------|------|
| **当前** (10.0/0.5/压制开) | 0.030 | 0.414-0.570 | ❌ 无区分度 |
| 调整PPL (0.15/0.5/压制开) | 0.045 | 0.327-0.600 | ⚠️ 略有改善 |
| 调整Vote (10.0/0.05/压制开) | 0.058 | 0.313-0.653 | ⚠️ 中等改善 |
| **两者都调** (0.15/0.05/压制开) | 0.075 | 0.237-0.683 | ✅ 明显改善 |
| **移除压制** (0.15/0.05/压制关) | **0.192** | **0.186-0.804** | ✅✅ 最佳 |

**但路由决策仍相同**: 即使调整参数，所有方案仍然产生48/52的簇级划分，因为Vote平均值恰好是0.5。

### 根本性问题

**Edit vs Gen模式性能差距不明显**:
- PPL几乎相同（gap平均0.017）
- Vote比例接近50-50
- 这表明在当前数据集上，**Edit和Gen模式本质上难以区分**

**实验设计的悖论**:
- 如果Edit和Gen本来就差不多，动态路由的价值何在？
- Pure Edit达到78.9%，动态路由仅74.2%
- **6.7%的性能损失**表明引入Gen mode是"得不偿失"
